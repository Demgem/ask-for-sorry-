# Sibling apology simulator as a pure static site

A multi-screen apology flow built entirely in vanilla HTML/CSS/JS, designed to guilt-trip a sibling into forgiving the sender. The implementation is a state machine driving transitions across ~14 screens: fingerprint scan, loading sequences, anger detection, a 10-level YES confirmation gauntlet, a NO-rejection path with an evasive button, advanced protocol escalation, celebration with confetti, shayari cards, a meme screen, and a memory gallery. Ships as three files with no build step, no dependencies, and no network calls.

Watch for: **contenteditable XSS vector** in the gallery captions (confirmed), **DOM element accumulation** from repeated confetti/sparkle generation without cleanup in all paths (confirmed), **gallery images only try .jpg** while meme tries four formats (confirmed asymmetry).

## High-level view

The `contenteditable` gallery captions are the one real security surface — any pasted HTML becomes part of the DOM, and CSP `style-src 'unsafe-inline'` weakens the usual mitigations for injected content.

Particle effects (confetti, sparkles) share a container and race on cleanup. `triggerMiniConfetti` sets a 4-second cleanup timeout, but the compliment card only displays for 2 seconds before the next screen fires. The celebration confetti (60 elements) never cleans up at all across restart cycles.

The NO button escape runs a document-level `mousemove` listener that calls `getBoundingClientRect()` on every event without throttling. Harmless on most hardware, but wasteful on high-refresh displays.

The NO flow provides identical visual feedback (same anger level, same message) from attempt 5 through attempt 12, making the experience feel stalled for 7 consecutive clicks before the advanced protocol triggers.

## Contenteditable as an XSS surface

The gallery section creates `<div contenteditable="true">` elements for photo captions. The initial value is set safely with `textContent`, but once the user interacts, they can paste arbitrary HTML (including `<img onerror=...>` or `<a href="javascript:...">` in browsers that don't fully enforce CSP on pasted content). This is a latent vector if the page is ever embedded in a larger context or served with a relaxed CSP. Replacing `contenteditable` with a styled `<input>` eliminates the risk entirely.

```javascript
// Current
caption.setAttribute('contenteditable', 'true');
caption.textContent = 'Memory ' + i + ' - Click to edit caption';

// Safer alternative
var caption = document.createElement('input');
caption.className = 'gallery-caption';
caption.value = 'Memory ' + i + ' - Click to edit caption';
```

## Confetti lifecycle and DOM accumulation

`triggerMiniConfetti` schedules a cleanup at t+4000ms. But the compliment card only shows for 2000ms before `showYesLevel` is called. If the next YES confirmation triggers new confetti before the old timeout fires, the timeout clears the new confetti instead of the old. More significantly, `createConfetti` on the celebration screen never cleans up — those 60 elements persist in the DOM if the user restarts and re-reaches celebration.

A cleaner pattern: clear the confetti container on every `showScreen` call, and cancel any pending cleanup timeouts via a stored timeout ID.

## Gallery format asymmetry

```javascript
// Meme: tries gif, jpg, png, webp with fallback chain
var formats = ['gif', 'jpg', 'png', 'webp'];

// Gallery: hardcoded to jpg only
img.src = 'images/memory' + i + '.jpg';
```

The README says "Supports JPG, PNG, GIF, WEBP formats" for gallery images. The code doesn't deliver on that claim. Either replicate the `tryFormat` fallback pattern for gallery images or correct the README.

## Mousemove handler performance

When the no-flow screen is active, every mouse move triggers `getBoundingClientRect()` and distance math. On a 240Hz display that's 240 calls/second. Wrapping in `requestAnimationFrame` batches to once per frame:

```javascript
var rafPending = false;
document.addEventListener('mousemove', function(e) {
    if (state.currentScreen !== 'screen-no-flow') return;
    if (rafPending) return;
    rafPending = true;
    requestAnimationFrame(function() {
        rafPending = false;
        // existing escape logic
    });
});
```

## NO flow plateau from attempt 5 to 12

The anger level array `[0.5, 1.5, 2.5, 3.5, 4.5]` maps to NO attempts 1-5. From attempt 6 through 12, `angerIndex` is clamped at 4, so the meter stays at 4.5/5 and the message stays at `'\u{1F91D} Sibling bond too strong.'` for 7 consecutive clicks. The `NO_MESSAGES` array has 12 entries but only indices 0-4 are effectively reachable in the no-flow screen (indices 5-11 duplicate earlier entries anyway). Either extend the array with unique messages and index them by `noCount` directly, or cycle through them modulo the array length.
